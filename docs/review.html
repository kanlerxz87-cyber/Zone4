How to use this page

Four steps. Step one takes ten minutes: 13 proposals, each with the problem it solves and the check that proves it worked.

  1. Read the twelve proposals. Each has its problem, its proposed change, its cost, its risk and the check that proves it worked. Four carry a dated partial or full application from 2026-11-19, and each of those says exactly what shipped and what is still waiting on you; the rest are proposals only.
  2. Answer the twelve questions, or let the defaults stand. Each question records what is already known, what is missing, who can supply it and how to discover it. Where a default exists it is named in the discovery step, so silence is still a recorded decision rather than a gap.
  3. Mark each proposal Accepted, Rejected or Parked. Record the choice with the date in this register (data/redesign.json). Accepted proposals become the next build's scope; the check field becomes its acceptance test.
  4. Only then build. The build order is the priority order: P1 first, because the tracking-ID test (RQ-02) decides whether any of the rest can earn.
